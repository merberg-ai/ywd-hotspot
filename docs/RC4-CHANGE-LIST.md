- RC4 hardening checkpoint before this list: `b6198635b8cd6e3d0fbf365161597b0fb4605f66`.

## Planned RC4 changes

### 1. Bring system/login/update presentation up to date with TGIF support

The appliance still has presentation surfaces that reflect the older BrandMeister-only/network model. Update the relevant generated/static presentation so the current integrated-network capability is represented consistently.

Scope to inspect and update during implementation:

- `/etc/issue` content installed/generated by YWD-Hotspot;
- `/etc/motd` content installed/generated by YWD-Hotspot;
- GitHub/update-script banner, summary, or status text where network capability is described;
- related source templates/install/update ownership so upgrades and fresh installs produce the same result.

Acceptance intent:

- BrandMeister and TGIF are represented as supported integrated networks where the surface describes network capability;
- no credentials are exposed;
- login/update presentation remains concise and readable on Pi Zero terminals;
- source install, update, and factory-image paths do not drift from one another.

### 2. Show TGIF in the Confirm Import Settings / restore preview

The encrypted `.ywdsettings` payload already preserves TGIF configuration and credentials, and live restore acceptance has passed. The human-readable confirmation/preview still needs TGIF parity with BrandMeister.

Add redacted TGIF information to the normal WebUI import confirmation and any equivalent first-boot/setup restore preview that uses the same backup format.

Minimum preview fields:

- TGIF enabled/disabled;
- TGIF master/host;
- TGIF port;
- TGIF password configured: yes/no only.

Rules:

- never display the TGIF password itself;
- preserve existing BrandMeister preview behavior;
- keep preview read-only and redacted;
- ensure normal WebUI restore and first-boot/setup restore present equivalent network information where applicable.

Acceptance intent:

- an operator can verify both BrandMeister and TGIF network intent before committing a restore;
- preview changes do not alter the encrypted backup format or restore semantics;
- existing encrypted backup/restore regression and live preservation behavior remain intact.
